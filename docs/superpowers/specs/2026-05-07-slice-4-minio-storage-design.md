**Date:** 2026-05-07
**Status:** Draft (pending user review)
**Phase:** 4 of N
**Parent project:** NeuroScan Workstation — local-first MRI / DICOM platform
**Branch:** `slice-4-minio-storage` (off `main`)
**Predecessors:** Slices 1, 2, 3 — all merged to `main`

## 1. Purpose

Add a content-addressed S3-compatible object store (MinIO) as a **sidecar** to Orthanc. Every DICOM that enters NeuroScan — whether uploaded by a clinician or generated by the reconstruction service — is also written to MinIO under a SHA-256-derived path. A `storage_objects` table records the metadata. A presigned-URL endpoint mints short-TTL S3 URLs that allow downstream systems to fetch a specific file without going through the API service.

This slice exists to demonstrate the "secure clinical data transmission" capability the parent PRD called for — checksumming, content-addressed storage, signed URLs, audit trail — without coupling the existing upload pipeline to a new failure domain. MinIO is best-effort: if it's down, uploads still succeed.

The slice also lays groundwork for Slice 10+ (real cloud deployment to AWS S3 / GCS): swapping the `endpoint_url` from MinIO to AWS is the only code change required.

## 2. Out-of-scope (deliberately deferred)

- Encryption at rest beyond what MinIO provides by default
- Customer-managed encryption keys (KMS, etc.)
- Multi-region / cross-region replication
- Lifecycle policies (auto-delete after N days)
- Presigned PUT URLs (client uploads bytes directly to MinIO bypassing api-service) — that's a Slice 9 concern alongside the job queue
- Persistent storage for raw k-space inputs (still tempfile-only; revisit if Slice 9 needs job replay)
- Per-user / per-role access control on storage objects (Slice 6 — auth)
- De-identification scanning before upload (Slice 5)
- Real cloud (AWS S3, GCS) — Slice 10+
- Server-side cleanup of orphaned objects (objects in MinIO with no `storage_objects` row)
- Storage usage dashboards / metrics (Slice 7 — Prometheus/Grafana)

These are explicit deferrals.

### Bucket layout

Single bucket `neuroscan`, two prefixes:

```text
neuroscan/
├── dicom/
│   ├── <sha256>.dcm        # bytes uploaded to /api/dicom/upload
│   └── ...
└── reconstructed/
    ├── <sha256>.dcm        # output of /api/reconstruction/jobs
    └── ...
```

Content-addressed paths mean uploading the same bytes twice is a no-op (the second PUT overwrites with identical content). No PII in object keys. Dedup is automatic.

### Failure handling

- **Orthanc fails** (existing Slice 1 behavior): upload returns 502, audit row records `failure`. Unchanged.
- **MinIO fails** (NEW): upload still returns 201, audit row records `status=success_minio_skipped` with the MinIO error in `message`. No `storage_objects` row written. `/health` reports `minio_reachable: false`.
- **Postgres fails**: pre-existing failure mode; the upload as a whole fails. No change.

### Architectural decisions (locked)

| ID | Decision | Rationale |
|---|---|---|
| AD-S4-1 | MinIO is a **sidecar** to Orthanc; Orthanc remains source of truth for pixel data | Doesn't rewire Slice 1's upload path. Demonstrates object storage + signed URLs without breaking existing tests. |
| AD-S4-2 | Both DICOM uploads AND reconstructed outputs are tee'd to MinIO | Symmetric: every DICOM in Orthanc has a MinIO copy. |
| AD-S4-3 | Single bucket `neuroscan`, prefixes `dicom/` and `reconstructed/` | Content-addressed flat-ish layout; natural dedup; no PII in keys; prefix listing covers "show all reconstructions". |
| AD-S4-4 | Best-effort writes; MinIO down does not block upload; audit + `/health` report it | Sidecar = availability of MinIO doesn't gate the pipeline. Honest reporting. |
| AD-S4-5 | **boto3** as the S3 client (not minio-py) | Universal S3 client. Trivial migration to AWS in Slice 10+ — only `endpoint_url` differs. |
| AD-S4-6 | Presigned URLs via `GET /api/storage/objects/{id}/presigned-url`; default TTL 300s, max 3600s | Read-only signed URLs only. Presigned PUT is Slice 9. |
| AD-S4-7 | "Share link" button on the audit page row, looked up by checksum | Visible UI surface with minimal frontend code. |
| AD-S4-8 | `storage_objects` is independent of `audit_events` and `reconstruction_jobs`; joined by `sha256` | Avoids polymorphic FKs. `source` column ('dicom_upload' / 'reconstruction_output') tags origin. |
| AD-S4-9 | New `audit_events.event_type` value: `dicom_uploaded` keeps the existing event_type but `status` gains a third value: `success_minio_skipped` | Existing schema accommodates the new state without migration. Slice 1's `Literal["success", "failure"]` is widened. |
| AD-S4-10 | Bucket auto-created at api-service startup if missing | Removes operational setup. Idempotent boto3 `create_bucket` with `BucketAlreadyOwnedByYou` swallowed. |

## 4. Data flows

### 4.1 DICOM upload (Slice 1 path, modified)

1. Client `POST /api/dicom/upload` with multipart `file=…`
2. api-service: validate DICOM, compute sha256, POST to Orthanc as before.
3. **NEW:** if Orthanc succeeded, attempt MinIO PUT to `dicom/<sha256>.dcm`:
   - On success: write `audit_events` row with `status=success` AND write a `storage_objects` row (`source=dicom_upload`).
   - On failure: write `audit_events` row with `status=success_minio_skipped` and the MinIO error in `message`. Do NOT write `storage_objects`. Log a warning.
4. Return 201 with the existing response shape (no new fields). The MinIO state is observable via the audit row and via `GET /api/storage/objects?sha256=…`.

### 4.2 Reconstruction output (Slice 3 path, modified)

1. `job_runner.run_job` does its existing work: load → reconstruct → metrics → write DICOM → POST to Orthanc.
2. **NEW:** between Orthanc upload and the final job-status update, attempt MinIO PUT to `reconstructed/<sha256>.dcm`:
   - On success: write a `storage_objects` row (`source=reconstruction_output`).
   - On failure: log a warning, do NOT write the row. The job is still marked `completed` (a missing MinIO copy doesn't fail the reconstruction).
3. The job's `output_dicom_uid` and `output_orthanc_instance_id` are unchanged. Tests that verify the recon flow continue to pass.

### 4.3 Presigned URL retrieval

1. `GET /api/storage/objects/{id}/presigned-url?expires=300`
2. api-service looks up the storage_object row, asserts it exists and bucket+key are non-empty.
3. Calls boto3 `generate_presigned_url("get_object", Params={"Bucket": …, "Key": …}, ExpiresIn=expires)`.
4. Returns `{ "url": "<presigned URL>", "expires_at": "<ISO timestamp>" }`.
5. The URL is valid for the requested TTL (clamped to `[60, 3600]`). The client (browser, curl, downstream system) uses it directly against MinIO; api-service is not in the data path for the actual GET.

### 4.4 Storage list / detail

- `GET /api/storage/objects?limit=&offset=&source=&sha256=` returns paginated rows. Filterable by `source` (`dicom_upload` | `reconstruction_output`) and by `sha256` (exact match — useful for "find the storage object for this audit row").
- `GET /api/storage/objects/{id}` returns one row.

### 4.5 Health

`/health` gains `minio_reachable: bool`. Slice 1's response shape stays additive — same keys plus the new one. `status` returns `"degraded"` if MinIO is down (downgraded from `"ok"`) but the response code stays 200 (Orthanc + DB are still reachable). 503 is reserved for the existing case (Orthanc OR Postgres unreachable).

### 4.6 Audit page "Share link" button

1. The audit row already has a `checksum_sha256` column.
2. New: when the audit panel renders, the React app calls `GET /api/storage/objects?sha256=<row.checksum>&limit=1` for each row that has a non-null checksum. Result is cached.
3. If a storage_object exists, the row gets a "Share link" button. Clicking it calls the presigned-url endpoint and copies the URL to the clipboard.
4. If no storage_object exists (MinIO was down at upload time, OR row predates Slice 4), the button is omitted.

### 6.1 `app/clients/s3.py`

```python
"""Sync S3 client backed by boto3, configured for MinIO endpoint by default."""

from __future__ import annotations

import logging
from datetime import datetime, timedelta, timezone

import boto3
from botocore.client import Config
from botocore.exceptions import BotoCoreError, ClientError

logger = logging.getLogger(__name__)


class S3Error(Exception):
    """Raised when an S3 operation fails after retries."""


class S3Client:
    def __init__(
        self,
        *,
        endpoint_url: str,
        access_key: str,
        secret_key: str,
        bucket: str,
        region: str = "us-east-1",
    ) -> None:
        self._bucket = bucket
        self._region = region
        self._client = boto3.client(
            "s3",
            endpoint_url=endpoint_url,
            aws_access_key_id=access_key,
            aws_secret_access_key=secret_key,
            region_name=region,
            config=Config(
                signature_version="s3v4",
                retries={"max_attempts": 3},
                s3={"addressing_style": "path"},
            ),
        )

    @property
    def bucket(self) -> str:
        return self._bucket

    def ensure_bucket(self) -> None:
        try:
            self._client.head_bucket(Bucket=self._bucket)
        except ClientError as exc:
            code = exc.response.get("Error", {}).get("Code")
            if code in ("404", "NoSuchBucket"):
                self._client.create_bucket(Bucket=self._bucket)
                return
            raise S3Error(f"head_bucket failed: {exc}") from exc

    def put_object(
        self,
        *,
        key: str,
        body: bytes,
        content_type: str = "application/dicom",
    ) -> None:
        try:
            self._client.put_object(
                Bucket=self._bucket,
                Key=key,
                Body=body,
                ContentType=content_type,
            )
        except (BotoCoreError, ClientError) as exc:
            raise S3Error(f"put_object {key} failed: {exc}") from exc

    def head_object(self, key: str) -> dict:
        try:
            return self._client.head_object(Bucket=self._bucket, Key=key)
        except ClientError as exc:
            raise S3Error(f"head_object {key} failed: {exc}") from exc

    def is_reachable(self) -> bool:
        try:
            self._client.list_buckets()
            return True
        except (BotoCoreError, ClientError):
            return False

    def generate_presigned_get_url(
        self, key: str, *, expires_in: int = 300
    ) -> tuple[str, datetime]:
        try:
            url = self._client.generate_presigned_url(
                "get_object",
                Params={"Bucket": self._bucket, "Key": key},
                ExpiresIn=expires_in,
            )
        except (BotoCoreError, ClientError) as exc:
            raise S3Error(f"presign {key} failed: {exc}") from exc
        return url, datetime.now(timezone.utc) + timedelta(seconds=expires_in)
```

```python
class StorageObject(Base):
    __tablename__ = "storage_objects"

    id: Mapped[int] = mapped_column(
        BigInteger().with_variant(Integer(), "sqlite"),
        primary_key=True,
        autoincrement=True,
    )
    bucket: Mapped[str] = mapped_column(String(64), nullable=False)
    object_key: Mapped[str] = mapped_column(String(256), nullable=False)
    sha256: Mapped[str] = mapped_column(String(64), nullable=False)
    content_type: Mapped[str] = mapped_column(String(64), nullable=False)
    size_bytes: Mapped[int] = mapped_column(BigInteger, nullable=False)
    source: Mapped[str] = mapped_column(String(32), nullable=False)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        nullable=False,
        default=lambda: datetime.now(timezone.utc),

        UniqueConstraint("bucket", "object_key", name="uq_storage_bucket_key"),

        Index("idx_storage_source", source),
        Index("idx_storage_created_at", created_at.desc()),
```

## 11. Data model

```sql
CREATE TABLE storage_objects (
  id              BIGSERIAL PRIMARY KEY,
  bucket          VARCHAR(64) NOT NULL,
  object_key      VARCHAR(256) NOT NULL,
  sha256          VARCHAR(64) NOT NULL,
  content_type    VARCHAR(64) NOT NULL,
  size_bytes      BIGINT NOT NULL,
  source          VARCHAR(32) NOT NULL,    -- 'dicom_upload' | 'reconstruction_output'
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT uq_storage_bucket_key UNIQUE (bucket, object_key)

CREATE INDEX idx_storage_sha256     ON storage_objects (sha256);
CREATE INDEX idx_storage_source     ON storage_objects (source);
CREATE INDEX idx_storage_created_at ON storage_objects (created_at DESC);
```

## 12. Testing strategy

### Unit tests (≥ 10 new)

- `test_s3_client.py` (moto-backed, ≥ 6 tests):
  - `ensure_bucket` creates if absent
  - `ensure_bucket` no-ops if present
  - `put_object` succeeds and is retrievable via `head_object`
  - `is_reachable` returns True when bucket exists
  - `generate_presigned_get_url` returns a URL containing `X-Amz-Signature`
  - presigned URL `expires_at` matches the requested TTL
- `test_storage_service.py` (≥ 4 tests):
  - `tee_to_s3` writes a row on success
  - `tee_to_s3` returns None and writes no row on S3 failure
  - `tee_to_s3` is idempotent on duplicate sha256 (UniqueConstraint either rejected gracefully or upsert-equivalent)
  - `mint_presigned_url` 404s for unknown id

### Integration tests (≥ 4 new, testcontainers MinIO + Postgres + Orthanc)

- POST DICOM → `audit_events.status=success` AND `storage_objects` row exists with matching sha256.
- POST reconstruction job → on completion, `storage_objects` row with `source=reconstruction_output` exists.
- `GET /api/storage/objects/{id}/presigned-url` returns a URL; `httpx.get(url)` returns the original DICOM bytes.
- MinIO container stopped mid-test → POST DICOM still returns 201, audit row has `status=success_minio_skipped`, no `storage_objects` row.

6. Wait 5 minutes (or pass `?expires=60` and wait 1 min) → URL returns 403 SignatureDoesNotMatch.

Existing `python` job runs the new tests. testcontainers spins MinIO alongside the existing Postgres + Orthanc containers. No new CI workflow file.

## 13. Non-functional requirements

- MinIO `put_object` for a < 10MB DICOM: < 500ms on a developer laptop.
- Presigned URL minting: < 50ms.
- `/health` round-trip including all three reachability checks: < 1s.
- Bucket auto-creation on api-service startup adds < 1s to startup time.
- `tee_to_s3` runs synchronously inline with the upload; the existing 5s upload NFR (Slice 1 §11) is widened to 6s to accommodate.

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| boto3 retries on 5xx default to 4 attempts; can stretch upload latency on degraded MinIO | Explicit `retries={"max_attempts": 3}` in `S3Client.__init__`. |
| MinIO testcontainer slow to start (pulls ~150MB image) | Cache image locally; CI uses Docker layer cache. First run on a fresh runner takes ~30s; subsequent runs <5s. |
| Network storms during test runs (postgres + orthanc + minio + ASGI) | Session-scoped containers in conftest reuse instances across tests. |
| `head_bucket` on first startup against a not-yet-ready MinIO can race | Wait-for-healthy in compose; api-service `depends_on: minio: condition: service_healthy`. |
| Presigned URLs leak in audit logs | URLs are minted on demand and never logged by api-service. They're only returned in the API response. |
| boto3 with virtual-hosted-style URLs vs path-style with MinIO | Set `s3 = {"addressing_style": "path"}` in boto3 Config. MinIO doesn't support virtual-host style without DNS fronting. |
| Content-addressed key collisions across `dicom/` and `reconstructed/` (same content from both paths) | Different prefixes ensure no collision; even if it happened, the row would be a duplicate but harmless. |

## 15. Definition of Done

Slice 4 is done when **all** of the following are true:

1. Alembic migration `003_storage_objects` runs cleanly on a fresh DB; table exists with all 8 columns + 3 indexes + unique constraint.
2. `MinIO` service is in `infra/docker-compose.yml` and reaches `healthy` within 30s of compose up.
3. Bucket `neuroscan` is auto-created on api-service startup if absent.
4. Uploading a DICOM via `POST /api/dicom/upload` writes both an `audit_events` row (`status=success`) and a `storage_objects` row with matching `sha256` and `source=dicom_upload`.
5. Reconstruction completion writes a `storage_objects` row with `source=reconstruction_output`.
6. With MinIO stopped: DICOM upload still returns 201, `audit_events.status=success_minio_skipped`, no `storage_objects` row.
7. `GET /api/storage/objects?source=dicom_upload` and `?source=reconstruction_output` return paginated rows.
8. `GET /api/storage/objects/{id}/presigned-url?expires=300` returns a URL that, when fetched directly, returns the original DICOM bytes.
9. Presigned URL with `expires=60` is rejected by MinIO after 60s.
10. `GET /health` returns `minio_reachable: true|false` and downgrades `status` to `"degraded"` (still HTTP 200) when MinIO is unreachable but DB+Orthanc are up.
11. Audit page in the React app shows a "Share link" button on rows whose checksum has a corresponding storage_object; clicking copies a presigned URL.
12. `pytest tests/unit/` adds ≥ 10 new tests; full unit suite stays green.
13. `pytest tests/integration/` adds ≥ 4 new tests; full integration suite stays green.
14. `ruff check` + `ruff format --check` clean.
15. `npm run typecheck` + `npm run build` clean.
16. `docs/qa-validation-plan.md` has TC-09 documented.
17. README quickstart mentions MinIO console URL.
18. `docs/status.md` and `docs/roadmap.md` updated to mark Slice 4 done.
